== Overview

The HTTP Server module exposes the SQL Notebook backend over a simple REST API using an embedded Jetty 12 server.
It bridges the frontend notebook UI with the `ConnectionRegistry` and `QueryExecutor` modules, allowing browsers to list configured namespaces and submit SQL queries.

No external server installation is required — the server starts automatically when the application launches.

== Starting the Server

The server is started programmatically via `HttpServer`:

[source,java]
----
HttpServer server = new HttpServer(registry, executor, 8080);
server.start();
----

By default the server listens on port `8080`. The port is configurable via the constructor.

== Endpoints

=== GET /namespaces

Returns the set of all configured namespace names loaded from `sql.properties`.

==== Request

[source]
----
GET /namespaces
----

No request body or parameters required.

==== Response

[source,json]
----
["prod", "staging", "local"]
----

[cols="1,3"]
|===
| Status Code | Meaning

| `200 OK`
| Returns a JSON array of namespace name strings.
|===

==== Example (curl)

[source,bash]
----
curl http://localhost:8080/namespaces
----

=== POST /query

Executes a SQL statement against a named namespace and returns the full result set.

==== Request

Content-Type: `application/json`

[source,json]
----
{
  "namespace": "local",
  "sql": "SELECT id, name FROM users LIMIT 10"
}
----

[cols="1,1,3"]
|===
| Field | Type | Description

| `namespace`
| String (required)
| The namespace name as defined in `sql.properties`.

| `sql`
| String (required)
| The SQL statement to execute.
|===

==== Response (Success)

[source,json]
----
{
  "namespace": "local",
  "sql": "SELECT id, name FROM users LIMIT 10",
  "columns": ["id", "name"],
  "rows": [
    ["1", "Alice"],
    ["2", "Bob"]
  ],
  "executionTimeMs": 42,
  "success": true,
  "errorMessage": null
}
----

==== Response (Query Error)

If the SQL itself is invalid or fails at the database level, the server still returns `200 OK` — the error is surfaced inside the response body. This allows the notebook UI to display the error inline in the cell.

[source,json]
----
{
  "namespace": "local",
  "sql": "SELECT * FROM nonexistent_table",
  "columns": [],
  "rows": [],
  "executionTimeMs": 5,
  "success": false,
  "errorMessage": "Table 'nonexistent_table' doesn't exist"
}
----

==== Error Responses

[cols="1,3"]
|===
| Status Code | Meaning

| `400 Bad Request`
| Request body is missing, not valid JSON, or `namespace`/`sql` fields are absent or blank.

| `404 Not Found`
| The specified `namespace` does not exist in the registry.

| `500 Internal Server Error`
| An unexpected server-side error occurred during execution.
|===

==== Example (curl)

[source,bash]
----
curl -X POST http://localhost:8080/query \
  -H "Content-Type: application/json" \
  -d '{"namespace": "local", "sql": "SELECT 1"}'
----

== Error Response Format

All error responses share a consistent JSON structure:

[source,json]
----
{
  "error": "Human-readable error message"
}
----

== Implementation Notes

=== Jetty 12 + EE10

Jetty 12 restructured its servlet support. The servlet context handler now lives under the `ee10` artifact:

[source,kotlin]
----
implementation("org.eclipse.jetty.ee10:jetty-ee10-servlet:12.0.15")
----

And imports use the `jakarta.servlet` namespace (not `javax.servlet`):

[source,java]
----
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
----

=== Request Body Reading

Jetty 12 does not reliably support `req.getReader()` in all configurations. Request bodies are read via `InputStream` instead:

[source,java]
----
String rawBody = new String(req.getInputStream().readAllBytes());
body = mapper.readTree(rawBody);
----

=== Query Errors vs HTTP Errors

SQL execution errors (bad SQL, missing table, type mismatch) are returned as `200 OK` with `success: false` in the payload. Only infrastructure-level problems (unknown namespace, missing fields) produce non-200 HTTP status codes. This distinction keeps the notebook UI simple — every cell response has the same shape.
