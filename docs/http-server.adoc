== Overview

The HTTP Server module embeds a Jetty 12 server and mounts all REST handlers. It is the integration point between every backend module and the browser frontend.

The server also serves the compiled React frontend from the `static/` resource directory, so no separate web server is needed.

== Starting the Server

[source,java]
----
HttpServer server = new HttpServer(registry, sourceRegistry, registrar, executor, 8080);
server.start();
----

Default port is `8080`. On successful startup the application opens the browser automatically at `http://localhost:8080`.

== Handler Map

[cols="1,1,2"]
|===
| Path | Handler | Description

| `/namespaces`
| `NamespaceHandler`
| Ping all namespaces and return health status

| `/connections/*`
| `ConnectionHandler`
| CRUD for persistent database connections

| `/query`
| `QueryHandler`
| Synchronous SQL execution over HTTP

| `/ws/query`
| `QueryWebsocket`
| Asynchronous SQL execution over WebSocket

| `/schema/*`
| `SchemaHandler`
| Table and column introspection per namespace

| `/sources/*`
| `FileSourceHandler`
| Upload files, register remote URLs, list and delete sources

| `/draft`
| `DraftHandler`
| Notebook draft persistence (save/load)

| `/browse`
| `FileBrowserHandler`
| Local filesystem browser for SQLite/DuckDB file selection
|===

== Endpoints

=== GET /namespaces

Returns health status for all registered namespaces. Each namespace is pinged with `SELECT 1` in parallel with a 3-second timeout.

Query parameter `all=true` includes ephemeral namespaces (uploaded files, remote URLs).
Without it, only persistent connections from `sql.properties` are returned.

==== Response

[source,json]
----
[
  { "name": "prod_pg",     "healthy": true,  "latencyMs": 4   },
  { "name": "analytics",   "healthy": false, "latencyMs": 3012, "error": "Connection refused" }
]
----

Results are sorted alphabetically by name for stable UI ordering.

'''

=== GET /connections/:namespace

Returns the config for a single namespace (password intentionally excluded).

[source,json]
----
{
  "namespace": "prod_pg",
  "type":      "postgresql",
  "host":      "db.internal",
  "port":      5432,
  "database":  "myapp",
  "username":  "app_user"
}
----

Returns `404` if the namespace is unknown or is an ephemeral source (file/remote).

'''

=== POST /connections/add

Register a new persistent database connection. Writes to `sql.properties` and hot-loads into the registry.

==== Request

[source,json]
----
{
  "namespace": "prod_pg",
  "type":      "postgresql",
  "host":      "db.internal",
  "port":      5432,
  "database":  "myapp",
  "username":  "app_user",
  "password":  "secret"
}
----

==== Response

[source,json]
----
{ "namespace": "prod_pg", "message": "Connection added" }
----

Returns `409` if the namespace already exists. Returns `400` for validation failures (see validation rules in `ConnectionHandler`).

'''

=== POST /connections/test

Test a connection without saving it. Uses `DriverManager` directly (not HikariCP) so no pool is created.

Request body is the same shape as `/connections/add`.

[source,json]
----
{ "success": true, "message": "Connection successful" }
----

On failure, returns a human-readable error (not the raw JDBC message):

[source,json]
----
{ "success": false, "message": "Connection refused — check host and port" }
----

'''

=== PUT /connections/:namespace

Update an existing connection. Supports renaming — the URL path is the old namespace name, the request body contains the new config including the new namespace name.

Internally: removes old entry from `sql.properties` + registry, writes and registers the new config.

Returns `404` if old namespace unknown. Returns `409` if new namespace name already exists.

'''

=== DELETE /connections/:namespace

Remove a persistent connection. Removes from `sql.properties` and closes the HikariCP pool.

[source,json]
----
{ "namespace": "prod_pg", "message": "Connection removed" }
----

Does not affect ephemeral namespaces — use `DELETE /sources/:namespace` for those.

'''

=== POST /query

Synchronous SQL execution. Blocks until the query finishes. Intended for scripting and testing; the frontend uses WebSocket for interactive queries.

==== Request

[source,json]
----
{ "namespace": "prod_pg", "sql": "SELECT id, name FROM users LIMIT 10" }
----

==== Response (success)

[source,json]
----
{
  "namespace":      "prod_pg",
  "sql":            "SELECT id, name FROM users LIMIT 10",
  "columns":        ["id", "name"],
  "rows":           [["1", "Alice"], ["2", "Bob"]],
  "executionTimeMs": 38,
  "success":        true,
  "errorMessage":   null
}
----

SQL-level errors return `200 OK` with `success: false` — the error is in `errorMessage`, not the HTTP status. Only infrastructure failures (unknown namespace, missing fields) produce non-200 status codes.

==== Error Responses

[cols="1,3"]
|===
| Status | Cause

| `400`
| Empty body, invalid JSON, or missing `namespace`/`sql` fields

| `404`
| Namespace not registered

| `500`
| Unexpected server error
|===

'''

=== GET /schema/:namespace

Returns all tables and columns for a namespace, including primary key and foreign key metadata. See `schema.adoc` for the full response shape and per-database behaviour.

Returns `404` for unknown namespaces and for ephemeral namespaces (file/remote sources — use `SELECT * FROM <view>` to explore their schema directly).

'''

=== POST /sources/upload

Upload a local file and register it as a DuckDB namespace. See `file-sources.adoc` for supported formats, size limits, and the full request/response shape.

'''

=== POST /sources/remote

Register a remote HTTP/HTTPS or S3 URL as a DuckDB namespace. See `file-sources.adoc`.

'''

=== GET /sources

List all registered file and remote data sources.

[source,json]
----
{
  "sources": [
    { "kind": "file",   "namespace": "sales_csv",    "filename": "sales data.csv", "addedAt": "2026-03-01T10:00:00Z" },
    { "kind": "remote", "namespace": "events_parquet", "url": "s3://bucket/events.parquet", "addedAt": "2026-03-02T09:00:00Z" }
  ]
}
----

S3 secret keys are always omitted from this response.

'''

=== DELETE /sources/:namespace

Remove a source. For file sources, deletes the uploaded file from disk. Deregisters the DuckDB namespace from the registry.

'''

=== GET /draft

Returns the current notebook draft. Returns `404` on first launch (no draft yet). If the draft file is corrupt, falls back to the latest backup automatically.

See `draft.adoc` for the full protocol and storage layout.

'''

=== POST /draft

Saves the full notebook state. Atomically writes the draft file and rotates the backup ring.

Requires a `version` field in the JSON body. Returns `{ "saved": true, "savedAt": "<ISO timestamp>" }` on success.

'''

=== GET /browse

Returns directory listings for local filesystem navigation. Used by the frontend file picker when adding a local SQLite or DuckDB file.

Restricted to safe roots (home directory, `/tmp`, common data directories). Path traversal is blocked — requests for paths outside the allowed roots return `403`.

== Error Response Format

All handlers use a consistent error shape:

[source,json]
----
{ "error": "Human-readable error message" }
----

== Implementation Notes

=== Jetty 12 + Jakarta EE10

All servlet imports use the `jakarta.servlet` namespace (not `javax.servlet`). The servlet context handler comes from the `jetty-ee10-servlet` artifact.

=== Request Body Reading

`req.getInputStream().readAllBytes()` is used instead of `req.getReader()` in `QueryHandler` because Jetty 12 does not reliably expose a buffered reader in all configurations. Other handlers use `req.getReader()` where the content is always text.

=== SQL Error vs HTTP Error

SQL execution errors (`success: false`) always return HTTP `200`. Only infrastructure failures produce non-200 status codes. This keeps the frontend logic uniform — every cell response has the same `QueryResult` shape regardless of outcome.
