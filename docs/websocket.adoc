= WebSocket Query Execution
:toc: left
:toclevels: 3
:sectnums:
:source-highlighter: rouge

== Overview

The WebSocket module exposes a persistent, bi-directional connection at `ws://localhost:8080/ws/query`.
It allows the notebook frontend to submit SQL queries and receive live status updates — without blocking or polling.

Unlike the `POST /query` HTTP endpoint (which blocks until the query finishes), the WebSocket endpoint immediately acknowledges receipt with a `running` message, then pushes the final result asynchronously when the query completes. Multiple cells can be in-flight simultaneously on a single connection.

== Endpoint

[source]
----
ws://localhost:8080/ws/query
----

== Message Protocol

=== Browser → Server (Incoming)

[source,json]
----
{
  "cellId":    "cell-1",
  "namespace": "local",
  "sql":       "SELECT id, name FROM users LIMIT 10"
}
----

[cols="1,1,3"]
|===
| Field | Type | Description

| `cellId`
| String (required)
| A unique identifier for the notebook cell. Echoed back in every response so the UI can route updates to the correct cell.

| `namespace`
| String (required)
| The namespace name as defined in `sql.properties`.

| `sql`
| String (required)
| The SQL statement to execute.
|===

=== Server → Browser (Outgoing)

The server always sends two messages per query submission:

==== 1. Running (immediate)

Sent immediately upon receiving the query, before execution begins.

[source,json]
----
{
  "cellId": "cell-1",
  "status": "running",
  "result": null,
  "error":  null
}
----

==== 2. Done (on completion)

Sent when the query finishes successfully.

[source,json]
----
{
  "cellId": "cell-1",
  "status": "done",
  "result": {
    "namespace":      "local",
    "sql":            "SELECT id, name FROM users LIMIT 10",
    "columns":        ["id", "name"],
    "rows":           [["1", "Alice"], ["2", "Bob"]],
    "executionTimeMs": 38,
    "success":        true,
    "errorMessage":   null
  },
  "error": null
}
----

==== 3. Done with SQL error (query failed at DB level)

If the SQL is invalid or fails at the database, `status` is still `done` but `result.success` is `false`.
This allows the UI to render the error inline in the cell without special-casing the message type.

[source,json]
----
{
  "cellId": "cell-1",
  "status": "done",
  "result": {
    "namespace":      "local",
    "sql":            "SELECT * FROM nonexistent_table",
    "columns":        [],
    "rows":           [],
    "executionTimeMs": 5,
    "success":        false,
    "errorMessage":   "ERROR: relation \"nonexistent_table\" does not exist"
  },
  "error": null
}
----

==== 4. Error (infrastructure-level failure)

Sent when the failure is not a SQL error but an infrastructure problem — unknown namespace, missing fields, malformed message.

[source,json]
----
{
  "cellId": "cell-3",
  "status": "error",
  "result": null,
  "error":  "Unknown namespace: unknown_ns"
}
----

== Error Conditions

[cols="2,3"]
|===
| Condition | Response

| Malformed JSON message
| `error` response with `cellId: "unknown"` and parse error description

| Missing `namespace` or `sql` field
| `error` response before any execution attempt

| Unknown namespace
| `running` then `error` (executor throws `ConnectionRegistryException`)

| Invalid SQL / DB-level failure
| `running` then `done` with `result.success: false`
|===

== Parallel Cell Execution

Multiple cells can be submitted on the same WebSocket connection simultaneously. Each message is processed independently on a virtual thread, so cell responses may arrive out of order. The `cellId` field is used by the frontend to route each response to the correct cell.

[source,json]
----
// Browser sends two queries back-to-back
{ "cellId": "cell-A", "namespace": "local", "sql": "SELECT 1" }
{ "cellId": "cell-B", "namespace": "local", "sql": "SELECT 2" }

// Server may respond in any order — cellId identifies which is which
{ "cellId": "cell-A", "status": "running", ... }
{ "cellId": "cell-B", "status": "running", ... }
{ "cellId": "cell-B", "status": "done",    ... }
{ "cellId": "cell-A", "status": "done",    ... }
----

== Example (JavaScript Client)

[source,javascript]
----
const ws = new WebSocket("ws://localhost:8080/ws/query");

ws.onopen = () => {
  ws.send(JSON.stringify({
    cellId:    "cell-1",
    namespace: "local",
    sql:       "SELECT id, name FROM users LIMIT 10"
  }));
};

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);

  if (msg.status === "running") {
    showSpinner(msg.cellId);
  } else if (msg.status === "done") {
    hideSpinner(msg.cellId);
    if (msg.result.success) {
      renderTable(msg.cellId, msg.result.columns, msg.result.rows);
    } else {
      renderError(msg.cellId, msg.result.errorMessage);
    }
  } else if (msg.status === "error") {
    hideSpinner(msg.cellId);
    renderError(msg.cellId, msg.error);
  }
};
----

== Implementation Notes

=== Jakarta WebSocket + Jetty 12

Jetty 12 uses the Jakarta WebSocket API (`jakarta.websocket`). The endpoint is annotated with `@ServerEndpoint` and registered programmatically via `JakartaWebSocketServletContainerInitializer`:

[source,java]
----
JakartaWebSocketServletContainerInitializer.configure(context, (ctx, wsContainer) -> {
    wsContainer.addEndpoint(QueryWebSocket.class);
});
----

=== Per-Connection Instance + Static Executor

Jakarta WebSocket creates a new `QueryWebSocket` instance for each browser connection. Shared dependencies (like `QueryExecutor`) are injected via a static reference set during server startup:

[source,java]
----
QueryWebSocket.setExecutor(executor);  // called once in HttpServer constructor
----

=== Virtual Threads for Non-Blocking Waits

After submitting a query to the `QueryExecutor` thread pool, the WebSocket message thread must not block while waiting for the `Future` result — doing so would prevent other messages from being processed on the same connection. A virtual thread is used to wait and push the response:

[source,java]
----
Thread.ofVirtual().start(() -> {
    QueryResult result = future.get();
    sendMessage(session, QueryResponse.done(cellId, result));
});
----
