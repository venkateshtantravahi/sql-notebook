= Query Executor
:toc: left
:toclevels: 3
:sectnums:
:source-highlighter: rouge

== Overview

The Query Executor is the JDBC execution engine. It accepts a namespace and SQL string, fetches a connection from `ConnectionRegistry`, runs the query on a fixed thread pool, and returns a `Future<QueryResult>`.

The executor is shared across all HTTP and WebSocket handlers. It is created once at startup and shut down cleanly on application exit.

== Classes

=== `QueryResult`

Immutable Java record representing the outcome of a single query. Returned both as `Future<QueryResult>` from the executor and directly serialised to JSON in HTTP and WebSocket responses.

[cols="1,1,3"]
|===
| Field | Type | Description

| `namespace`
| `String`
| Namespace the query ran against.

| `sql`
| `String`
| The SQL that was executed.

| `columns`
| `List<String>`
| Column names from the result set. Empty if the query produced no columns or failed.

| `rows`
| `List<List<Object>>`
| Result rows. Each row is a list of column values in column order. Empty on failure or empty result.

| `executionTimeMs`
| `long`
| Wall-clock time from connection acquisition to result extraction, in milliseconds.

| `success`
| `boolean`
| `true` for a successful query, `false` for a DB-level error or SQL failure.

| `errorMessage`
| `String`
| Error detail when `success` is `false`. `null` on success.
|===

==== Factory Methods

[source,java]
----
// Successful result
QueryResult.success(namespace, sql, columns, rows, executionTimeMs);

// Failed result (SQL error, connection error, etc.)
QueryResult.failure(namespace, sql, executionTimeMs, errorMessage);
----

=== `QueryExecutor`

Wraps a `ExecutorService` and submits each query as an independent task.

[source,java]
----
QueryExecutor executor = new QueryExecutor(registry);
Future<QueryResult> future = executor.execute("prod_pg", "SELECT * FROM users LIMIT 10");
QueryResult result = future.get(); // blocks until complete
----

==== Constructor

The thread pool size is calculated automatically from the number of registered namespaces at construction time:

[source]
----
poolSize = max(4, namespaceCount × 3)
----

This gives at least 4 threads with headroom for 3 concurrent queries per namespace. The pool size is fixed after construction — namespaces added at runtime do not resize it. For notebooks with many dynamically added file sources, the initial minimum of 4 is usually sufficient.

==== Methods

[cols="2,3"]
|===
| Method | Description

| `execute(namespace, sql)`
| Validates the namespace exists, then submits the query to the thread pool. Returns `Future<QueryResult>`. Throws `ConnectionRegistryException` synchronously if the namespace is unknown.

| `shutdown()`
| Initiates an orderly shutdown. In-flight queries complete before the pool terminates.
|===

=== `QueryExecutorException`

Thrown for executor-level failures that are not SQL errors (e.g. pool submission failures). Not thrown for invalid SQL — those are captured in `QueryResult.failure`.

== Parallel Execution

Each `execute()` call is an independent task. Multiple cells can be in-flight simultaneously without blocking each other, even against the same namespace.

[source,java]
----
Future<QueryResult> f1 = executor.execute("prod_pg", "SELECT * FROM orders");
Future<QueryResult> f2 = executor.execute("analytics_pg", "SELECT count(*) FROM events");

QueryResult r1 = f1.get();
QueryResult r2 = f2.get();
----

== Error Handling

[cols="2,3"]
|===
| Scenario | Behaviour

| SQL is invalid or fails at DB level
| `QueryResult.failure` with `errorMessage` from the JDBC exception. `success = false`. No exception thrown from `execute()`.

| Query returns no rows
| `QueryResult.success` with empty `rows` list. `success = true`.

| Unknown namespace
| `ConnectionRegistryException` thrown synchronously from `execute()` before any thread pool submission.

| Connection pool exhausted / timeout
| Captured inside the thread pool task. Returns `QueryResult.failure` with the HikariCP timeout message.
|===

== Tests

Located at `src/test/java/io/sqlnotebook/executor/QueryExecutorTest.java`

[cols="2,3"]
|===
| Test | What it validates

| `shouldReturnColumnsAndRows`
| Valid SELECT returns correct column names and row data

| `shouldReturnFailureForInvalidSql`
| Invalid SQL produces `success=false` QueryResult, no exception thrown

| `shouldReturnEmptyRowsForNoResults`
| Query with no matching rows returns empty list with `success=true`

| `shouldRunTwoQueriesInParallel`
| Two futures run concurrently and return independent correct results

| `shouldTrackExecutionTime`
| `executionTimeMs` is a positive, plausible value
|===
