= Config Parser
:toc: left
:toclevels: 3
:sectnums:
:source-highlighter: rouge

== Overview

The Config Parser reads `sql.properties` at startup, validates each connection block, and returns a `Map<String, ConnectionConfig>` that the rest of the application uses to initialise connection pools.

It is the only module that touches the filesystem for connection configuration. Everything above it (ConnectionRegistry, QueryExecutor, handlers) works purely with the in-memory map it produces.

== Classes

=== `ConnectionConfig`

Immutable Java record holding connection details for a single database namespace.

[cols="1,1,2"]
|===
| Field | Type | Description

| `namespace`
| `String`
| Unique identifier for this connection. Lowercase letters, numbers and underscores only.

| `type`
| `String`
| Database type string. See supported types below.

| `host`
| `String`
| Database server hostname or IP. Empty string for SQLite and DuckDB (file-based).

| `port`
| `int`
| Database server port. `0` for SQLite and DuckDB.

| `database`
| `String`
| Database/schema name, or file path for SQLite and DuckDB.

| `username`
| `String`
| Login username. Empty string for SQLite and DuckDB.

| `password`
| `String`
| Login password. Empty string for SQLite and DuckDB.

| `poolSize`
| `int`
| Maximum concurrent connections in the HikariCP pool. Defaults to `5`.
|===

=== `ConfigParser`

Reads, parses, writes, and modifies `sql.properties`.

[source,java]
----
ConfigParser parser = new ConfigParser();

// Read all connections from disk
Map<String, ConnectionConfig> configs = parser.parse("sql.properties");

// Append a new connection block
ConfigParser.write("sql.properties", config);

// Remove a connection block by namespace
parser.remove("sql.properties", "old_namespace");
----

=== `ConfigException`

Thrown when the file is malformed, a required field is missing, the type is unsupported, or the port value is invalid.

== Configuration Reference

=== File Format

Each namespace is a flat block of properties with the namespace name as the prefix.
The separator is a dot — `<namespace>.<field>=<value>`.

[source,properties]
----
# local_pg
local_pg.type=postgresql
local_pg.host=localhost
local_pg.port=5432
local_pg.database=myapp
local_pg.username=admin
local_pg.password=secret
----

SQLite only requires `type` and `database` (a file path). All other fields are ignored.

[source,properties]
----
# my_sqlite
my_sqlite.type=sqlite
my_sqlite.database=/Users/me/data/local.db
----

=== Supported Database Types

[cols="1,2,1"]
|===
| Type string | Database | Requires host/port/user?

| `mysql`
| MySQL 8+
| Yes

| `postgresql`
| PostgreSQL 13+
| Yes

| `oracle`
| Oracle 19c+
| Yes

| `microsoft-sql-server`
| SQL Server 2019+
| Yes

| `sqlite`
| SQLite 3
| No — file path in `database` field only

| `duckdb`
| DuckDB 1.x
| No — file path in `database` field. Registered automatically by DuckDbRegistrar for file/remote sources; rarely set manually.
|===

=== Multiple Connections

Multiple namespaces can coexist in the same file. The parser groups them by prefix and processes each independently.

[source,properties]
----
# prod_mysql
prod_mysql.type=mysql
prod_mysql.host=prod-db.internal
prod_mysql.port=3306
prod_mysql.database=production
prod_mysql.username=app_user
prod_mysql.password=secret

# analytics_pg
analytics_pg.type=postgresql
analytics_pg.host=analytics-db.internal
analytics_pg.port=5432
analytics_pg.database=analytics
analytics_pg.username=analyst
analytics_pg.password=secret
----

Pool size is fixed at 5 per namespace. It is not currently configurable via `sql.properties`.

=== Missing File Behaviour

If `sql.properties` does not exist, `parse()` returns an empty map rather than throwing. The application starts normally with no connections — connections can be added at runtime via the `/connections/add` endpoint.

== Internal Behaviour

=== Parsing Pipeline

[source]
----
parse(configFile)
  │
  ├── Files.exists() check → return empty map if missing
  ├── Properties.load()    → flat key=value map
  ├── groupByNamespace()   → Map<String, Map<String, String>>
  └── buildConfig()        → validate + construct ConnectionConfig per namespace
----

=== Write and Remove

`write()` appends a new namespace block to the file and checks for duplicates first.
`remove()` rewrites the file line-by-line, skipping the target namespace's comment header, property lines, and blank separator.

Both operations are performed on the raw text level (not via `Properties`) so comment formatting is preserved.

== Error Handling

[cols="2,3"]
|===
| Scenario | Exception message

| File exists but cannot be read
| `Cannot read config file: <path> — <io error>`

| Required field missing
| `Missing required field '<field>' for namespace: <namespace>`

| Unsupported database type
| `Unsupported type '<type>' for namespace '<namespace>'. Supported: [...]`

| Invalid port (non-numeric or out of range)
| `Invalid port '<value>' for namespace: <namespace>`
|===
